## Confirmed failures

Three Python jobs failed during `python -m pip install .`:

```text
error: Multiple top-level packages discovered in a flat-layout:
['app', 'nginx', 'alembic', 'branding', 'monitoring'].
setuptools will not proceed with this build.
```

Affected jobs:

- Unit and integration;
- PostgreSQL migrations;
- PostgreSQL concurrency.

The security job invoked Gitleaks v8.30.1 with a flag that is not accepted by
the `git` subcommand:

```text
Error: unknown flag: --source
Process completed with exit code 126.
```

This was an invocation failure, not a reported secret finding.

After correcting the invocation, the default Gitleaks rules identified two
`generic-api-key` false positives. Both are the same fixed, public test-only
`ENCRYPTION_KEY` fixture:

- `.github/workflows/release-gates.yml`;
- `docker-compose.test.yml`.

The repository configuration keeps all default rules and narrowly allowlists
only the exact placeholder line when it occurs in either of those two paths.
The allowlist does not suppress other values, paths, or rules.

## Corrective policy

- setuptools uses an explicit build backend and discovers only `app` and
  `scripts`;
- templates and static assets are declared as `app` package data;
- Docker copies the required Python source before `pip install .`;
- Python installation uses explicit retry and timeout settings without an
  unrelated in-build pip self-upgrade;
- all Python CI jobs use the same local composite installation action;
- Gitleaks remains a fail-closed full-history scan;
- the Gitleaks image is pinned by immutable multi-platform manifest digest;
- the repository mount is read-only and Git `safe.directory` is explicit.
- pip-audit audits the local project dependency graph, so the unpublished
  `processing-platform` distribution is not misclassified as a missing PyPI
  dependency.

## Reproduce the Gitleaks gate

From Bash in the repository root:

```bash
docker run --rm \
  --user "$(id -u):$(id -g)" \
  --env GIT_CONFIG_COUNT=1 \
  --env GIT_CONFIG_KEY_0=safe.directory \
  --env GIT_CONFIG_VALUE_0=/repo \
  --volume "$PWD:/repo:ro" \
  --workdir /repo \
  ghcr.io/gitleaks/gitleaks@sha256:c00b6bd0aeb3071cbcb79009cb16a60dd9e0a7c60e2be9ab65d25e6bc8abbb7f \
  git --config /repo/.gitleaks.toml \
  --redact --no-banner --log-opts=--all /repo
```

Exit code `0` means the complete history was scanned with no finding. A
finding or scanner failure remains non-zero and fails the release gate.
