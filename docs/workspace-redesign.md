## Исправленные проблемы

### TeamLead: RUB и USDT

Сервис `teamlead_settlement_amounts()` используется предпросмотром и созданием
заявки. Действующая комиссия — 5 USDT сверх суммы получения. Сумма выплаты в RUB
и комиссия в RUB округляются **отдельно** до копеек с ROUND_HALF_UP; USDT имеет
шесть знаков. Доступный RUB уже исключает резерв, поэтому повторно резерв не
вычитается. Долг, текущая заявка и 168 часов после завершения выплаты блокируют
новый вывод по существующим правилам.

`teamlead_max_withdrawal()` находит максимальное число микродолей USDT, которое
помещается в доступный RUB после отдельно округлённой комиссии. Учитывается
исключительная верхняя граница половины копейки: следующая микродоля уже не должна
помещаться. Поэтому максимум может содержать небольшую дробную часть сверх простого
деления доступного RUB на курс — это следствие прежнего округления, а не новая комиссия.

`GET /staff/cabinet/teamlead/settlements/quote` — только собственный подтверждённый
кабинет TeamLead, ответ `no-store`. Режим `requested_usdt=max` вычисляет максимум,
комиссию и списание по одной свежей котировке. JavaScript не рассчитывает деньги.
После обновления одновременно меняются сумма и детали курса в карточке.
Создание заявки повторно проверяет актуальный курс и доступность под блокировкой.
При изменившейся котировке итог может измениться; это явно объясняется в форме.

Нет свежего Rapira ask — «Расчёт USDT недоступен» с причиной, без подставного курса
и ложного нуля. Отдельного USDT-баланса и конвертации при просмотре не возникает.

### Webhook мерчанта

Поиск по ID/типу/заказу/ошибке, статус, даты и сброс фильтров. Фильтры работают по
реальным последним 300 событиям, что явно указано рядом с количеством. В таблице —
время, попытки, статус и короткая ошибка; в диалоге — полные доступные подробности,
ограниченные по высоте JSON/ответы и копирование. Чувствительные ключи и заголовки
Authorization/Cookie, Basic/Bearer и вложенные секреты редактируются сервером.

### Растягивание кабинетов

Снято прежнее глобальное `overflow-x:hidden` у html/body. Исправлены размеры и
минимальные ширины контейнеров, адаптивная ширина боковой навигации, поля и локальная
прокрутка таблиц. Длинные данные переносятся или сокращаются с деталями/копированием.
Ширина всей страницы не скрывает ошибки компоновки.

## Трансгран

Подготовлены KZ→AM (KZT→AMD) и KZ→GE (KZT→GEL). Superadmin сохраняет черновики,
Merchant видит недоступность направления и валюты, Trader/Operator сохраняют
предпочтение страны/валюты участия. Место для будущих реквизитов обозначено явно.
Оба направления заблокированы на уровне интерфейса, серверного endpoint и ограничения
статуса БД. Контракт операции, валюты, котировка, комиссии, TTL, идентификаторы провайдера
и нерешённые вопросы описаны в [crossborder-contract.md](crossborder-contract.md).

## Локальный запуск на подготовленном ПК

Основное приложение: <http://127.0.0.1:8000/staff/login>.
Отдельные входы: `/merchant/login`, `/trader/login`, `/aggregator/login`.
Исходные рабочие аккаунты сохранены. QA-копия: <http://127.0.0.1:8001/staff/login>.

Открыть Docker Desktop, затем в PowerShell:

```powershell
Set-Location C:\Users\aimwa\Documents\ChatGPT\OzarkPay
.\run\docker\ozark.ps1 Start
.\run\docker\ozark.ps1 Status
```

Используется локальный `run/docker/compose.yml`, проект `ozarkpay-local`, пять
контейнеров: PostgreSQL, Redis, API, worker, beat. Настройки — `.env.docker.local`.
API слушает только localhost. Файлы `app/`, `scripts/`, `alembic/` подключены из
этого checkout; API перезагружается при изменениях Python. Для изменений задач Celery:

```powershell
.\run\docker\ozark.ps1 Restart
```

Миграция 0026 уже применена. При восстановлении более старой копии сначала сделать
резервную копию и выполнить `docker compose -f run/docker/compose.yml --env-file
.env.docker.local exec api alembic upgrade head` одной строкой.
`Stop` останавливает контейнеры без удаления данных. Не использовать `down -v`.
